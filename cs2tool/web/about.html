01这是什么

本地运行的 CS2 对局分析工具。把 .dem 丢进目录，它解析成可查的数据：能力画像、逐场趋势、武器与道具细节、残局与多杀、回合级回放。全部在你自己电脑上跑，不联网、不上传、不需要账号。

  • 解析层用开源的 awpy 3.1.1，不是自己写的解析器
  • 存储是单个 SQLite 文件（data/cs2.db），可以直接拷走
  • 回放按回合生成，四栏 HUD + 地图雷达 + 双轨回合轴
  • 导出 CSV 全量数据，能直接喂给 AI 分析
这个工具只读 demo，不读取游戏进程、不注入、不修改任何游戏文件。理论上不存在被 VAC 检测的风险，因为跟游戏本身没有任何交互。

02快速开始

解压即用，不需要装 Python（已经带了运行环境）。

  1. 双击 START.bat，浏览器自动打开 http://127.0.0.1:8790
  2. 把 .dem 放进 demos/ 目录（或点「从 CS2 拉取」）
  3. 打开 Demo 页 → 点「分析未处理」
  4. 等进度条走完，回主页看数据
第一次启动会创建 demos/、data/ 两个目录。所有东西都在程序自己那一层，删掉整个文件夹就干净了。

03导入 Demo

三种方式，按方便程度排。

从 CS2 自动拉取

CS2 客户端里打开「比赛记录」→ 下载 demo，文件会存到 <CS2 安装目录>\game\csgo\replays\。 在 Demo 页点 「⇩ 从 CS2 拉取」，工具会把这个目录里新的 .dem 复制过来并自动登记。

  • 找不到目录时，去设置里填「CS2 安装目录」，或者直接填 replays 路径
  • 已经存在的同名文件会跳过，不会重复复制
  • 拉取完不会自动解析，还要点一次「分析未处理」

手动复制

把 .dem 直接放进 demos/，然后点「扫描目录」。目录可以在设置里改成任意路径（比如 Steam 库所在的盘）。

目录同步

如果你用 Resilio / 坚果云之类的同步盘，把 demos/ 指向同步目录，别的机器下的 demo 会自动出现在这里，点「扫描目录」就能登记。

04解析流程

一次解析大概 8–15 秒（180 MB 的 demo、20 回合左右）。

点「分析未处理」后，工具会依次：

  1. 用 awpy 读 demo，加载 rounds / kills / damages / stats / shots / item_events / bomb / blinds / grenades / fires / smokes / round_economy 十二个数据集
  2. 把事件落进 SQLite（matches / players / rounds / kills / damage / pms / economy / blinds / purchases / round_end / weapon_stat / grenade_throw）
  3. 算派生指标（Rating 2.0、Impact、存活率、残局、多杀分桶等）
  4. 生成该场的回放数据（data/replays/<match_id>.json，约 3–5 MB）
分析未处理 ↻ 重算评分 ⟲ 重新解析
三个按钮的区别见下面「设置项」一章。

身份识别

工具需要知道「你」是哪个玩家，才能算个人数据。识别顺序：

  1. 读设置里存的 steamid
  2. 读数据库里标记过的玩家（is_me）
  3. 跨多场出现次数最多的那个 steamid 自动推断

推断错了就在顶栏下拉里手动选，选完会落库，以后不用再选。

同一台机器上如果有多个人玩，下拉里会列出所有出现过的玩家（括号里是参与场次）。切换玩家不会重新解析，只是换一套统计视角。

06武器指标

武器区用 ‹ 名字 › 左右切换，一次看一把。

指标定义算法
命中率开火里有几次打中产生伤害的开火次数 ÷ 总开火次数（同一 tick 配对）
局均击杀用这把枪的每回合击杀该武器击杀 ÷ 总回合
爆头率击杀里爆头的比例爆头击杀 ÷ 该武器击杀
阈值内低速开火率开火瞬间速度已降到能精确射击范围的比例（急停的代理指标）速度 ≤34 units/s 的枪械开火 ÷ 枪械开火数
超阈值速度开火率带着速度开火的比例（上项的补数）速度 >34 units/s 的枪械开火 ÷ 枪械开火数
穿墙击杀子弹穿透物体后击杀awpy penetrated 标记
穿烟击杀隔着烟雾击杀awpy thrusmoke 标记
跳跃击杀击杀瞬间自己处于腾空击杀 tick 上 is_jumping = true
盲狙击杀狙击枪不开镜击杀（仅狙击枪显示）awpy noscope 标记
为什么用速度而不是 inaccuracy：awpy 的 shots.inaccuracy 读的是武器实体的 m_fAccuracyPenalty（连发累积的精度惩罚），官方源码注释写明「CS2 does not network the fully-computed inaccuracy」——真正的散布由引擎实时算，不写进 demo。实测也印证：速度 0-5 与 120+ 的开火，该值中位数几乎相同（AK 约 0.020 vs 0.021）。而 snapshots 里的速度是引擎真实物理量，34 units/s 是步枪还能精确射击的临界值，跨场可直接比较。
跳跃击杀是 awpy 没有的字段，用击杀 tick 上的快照判定，起跳当帧可能落在相邻 tick，会有少量漏计。盲狙同理，只对标了 noscope 的击杀计数。
武器有类别：gun 枪械 / melee 近战 / util 投掷物。投掷物和刀也会触发 weapon_fire 事件（扔闪、挥刀都算），但那不是射击——所以命中率、急停率只对枪械计算，投掷物行的这两列留空。页面上的武器卡只轮播有击杀的枪械，CSV 里才看得到全部 29 行。
命中数与伤害对不上账是真实存在的口径差，不是 bug：
① 命中——总览用 awpy 的统计口径（320），武器明细用「开火 tick 与伤害 tick 配对」口径（270），差 50 次属于配对不上（穿墙、延迟结算）。CSV 里单独占一行 (未归属)，不静默丢弃。
② 伤害——总览的 dmg 是按剩余血量截断的（7517），武器明细是单次截断到 100 的原始伤害（9099），差 1582 是溢出伤害。对满血敌人打出 120 的爆头，前者记 100，后者记 100；但对只剩 20 血的敌人补一枪 100，前者记 20，后者记 100——这个差值不可能靠改代码消掉，只能分开标注。
所以不要用武器明细的 dmg 加总去核总览伤害，两者不是同一个量。
消音武器的伤害记在基础武器名下：CS2 的伤害事件不带 _silencer 后缀，M4A1-S 打出的伤害全记成 m4a1，所以 m4a1_silencer 有击杀却显示伤害为空（不是 0）。两把枪在事件层面无法拆开。

08多杀与残局

多杀看爆发力，残局看 1vN 的处理能力。

多杀

指标定义算法
2K / 3K / 4K / 5K+一回合恰好完成 N 次有效击杀按「玩家 × 回合」统计击杀数后分桶，不含自杀与环境死亡
多杀回合率至少 2 杀的回合占个人回合的比例多杀回合数 ÷ 个人计入回合数

残局

指标定义算法
残局机会成为本方唯一存活者、对方还有人按击杀事件重建存活人数，触发时记录
残局获胜 / 失败残局开始后本方最终输赢按回合结果归属
残局成功率赢下的残局占比获胜 ÷ 已结算机会（未确认结果的不进分母）
残局存活率残局里活到回合判定时点存活至回合末的残局数 ÷ 残局机会
残局击杀 / 伤害残局窗口内的产出残局起 tick 至回合判定 tick 内的击杀与伤害
保枪次数残局输了但自己活着，装备保住回合判定前 1 秒的快照：存活 + 持有装备
保枪率保枪次数占残局机会保枪 ÷ 残局机会
保留装备总额 / 平均保住的装备购置价按回合判定时点库存估值求和、取平均
残局输掉不等于没产出。一场残局完全可能输回合，但拿到击杀、伤害，还把枪保住——这三项是分开统计的。
残局机会总数 = 1v1~1v5 各档机会数之和，两者都从击杀事件流重建，同一个来源。awpy 自带的 clutch_played 在边界回合上和我们的重建结果会有出入（它的 roster 推导方式不同），所以总量以重建结果为准。
另外注意：awpy 的 clutch_1vN 字段统计的是赢下的次数（官方注释为 clutches won），不是机会数——所以它全为 0 只代表一次没赢，不代表没打过残局。

人数优势

指标定义算法
先形成人优势本方首次成为人数较多一方的回合占比优势回合 ÷ 总回合
优势转胜率拿到人数优势后赢下回合优势回合获胜数 ÷ 优势回合

09经济与道具

经济

指标定义算法
总支出整场买东西花掉的钱购买事件 cost 求和
每回合平均支出单回合消费总支出 ÷ 回合
每回合装备价值回合末人均携带装备估值装备估值按回合加权平均（落库时已是人均，不再除 5）
回合初继承装备回合开始时人均已有装备同上，取回合开始快照

装备价值是人均。CS2 满经济 5 人合计约 20,000，人均 4,000——如果看到人均上万，那一定是口径错了。

花费构成（CT / T 分别）

横向 100% 堆叠条，各段宽度就是占比。分八类：步枪 / 狙击枪 / 冲锋枪 / 霰弹机枪 / 甲 / 道具 / 手枪 / 钳子。

类别取数方式
步枪 / 狙击枪 / 冲锋枪 / 霰弹机枪 / 手枪 / 道具购买事件的 cost 精确求和，按武器名归类
甲反推：本回合现金支出 − 已知购买，剩下的就是甲
钳子m_bPawnHasDefuser 由无到有的回合 × $400（只有 CT）
购买事件里不含护甲和拆弹钳，这两项只能用「本回合实际花掉的钱」减去「已知买到的东西」倒推。所以「甲」是残差，可能包含极少量的其他漏计项。

道具

火 / 雷 / 烟 / 闪 / 诱饵五个独立面板：

指标定义算法
局均伤害火雷每回合造成的伤害（仅火雷）火雷伤害 ÷ 回合
每颗平均伤害一颗火雷打出多少伤害火雷伤害 ÷ 有效投掷数
有效投掷真的造成了伤害的投掷damage 事件按 tick 去重
购买 / 捡起买了几颗、捡了几颗item_events 的 purchase / pickup
每人次平均致盲每个被闪到的敌人平均瞎多久（仅闪光）致盲总秒数 ÷ 致盲人次
每颗闪到几人一颗闪光平均闪到几个人（仅闪光）致盲人次 ÷ 投出颗数
闪光效率投出的闪光里有多少生效生效闪光数 ÷ 投出数（只算敌方）
投掷次数已按人归属，来自 demoparser2 的引爆事件（详见下方「投掷者是怎么拿到的」）。买、捡、伤害、致盲同样是按人的。
闪光效率不能用「致盲人次 ÷ 投出数」——一颗闪光同时闪到 3 个人会算成 300%。这里是按闪光颗数去重。

从上到下 10 个区块，左侧固定锚点栏可跳转。顶部下拉切换「我」是谁。

概览平均 武器回合事件 多杀残局结束原因 地图数据经济 道具图池
顶部锚点栏：点一下跳到对应区块，滚动时会自动高亮当前位置。
  • 概览：三个并列大数（总回合 / 总伤害 / 总胜率）+ 一条 Rating 相关指标带。点指标名切换下方折线图，最多画最近 20 场。
  • 平均：8 项一行。右上角 全部 | CT | T 单击循环切换，切到单阵营时没有数据的项会隐藏。
  • 武器：‹ 名字 › 切换，一次一把，下面是枪法效率与特殊击杀。
  • 回合事件：首杀 / 补枪 / 拉枪三块，内部指标横排。
  • 多杀残局：多杀回合率放大 + 2K/3K/4K/5K 一行；残局两行（机会/胜/负/成功率/存活率/击杀/伤害 + 保枪四项），下面 1v1~1v5 明细表。
  • 结束原因：环形图，蓝=CT 橙=T，扇区上放 CS 官方图标，整圈缓慢旋转。标题右侧的问号点开是口径说明。

  • 经济：四项总额 + 购买类型胜率 + 逐场花费横条（带占比）。
  • 道具：五个独立面板，各自的购买 / 捡起 / 投出 / 伤害 / 致盲。
  • 图池：玩过哪些图、各自胜率。
平局是独立的第三种结果。MR12 先到 13 分算赢，常规打满 24 回合 12:12 就是平局（加时后 15:15 同理）。 平局既不算赢也不算输，胜率分母里不含它；如果打过平局，总胜率下面会显示「N 平 (X%)」。
加时局在比分后面标「加时」。换边规则：R1-12 / R13-24 换一次，加时每 3 回合换一次（R25-27 延续下半场）。

  • 回合轴：横轴回合序号，上下双轨表示胜负归属，图标编码获胜方式，半场/加时换边处有分隔
  • TAB 面板：整场计分板（K/D/A、爆头率、ADR、KAST、Rating、首杀、多杀、道具统计）

操作

  • 点回合轴任意一格切回合，播放中也能切
  • 准备期可跳过 / 快进
  • 默认只显示当前位置，轨迹要手动开
回放数据缓存在 data/replays/<match_id>.json，一场 3–5 MB。第一次打开某场要生成（约 30 秒），之后秒开。重新解析会清掉缓存。

15常见问题

页面打不开 / 白屏

多半是端口被占用（旧进程没退）。START.bat 会自动杀掉占用 8790 的旧进程再启动，如果还不行，看命令行窗口里的报错。

数据全是 0 或空白

  1. 顶部下拉选的人对不对（可能选到了没打过的人）
  2. Demo 页看状态是不是「失败」，鼠标停上去看错误
  3. 点一次「⟲ 重新解析」

回放打开很慢

第一次打开某场要生成缓存（约 30 秒）。之后秒开。

存活率看起来偏低

存活率 = (总回合 − 死亡回合) ÷ 总回合。如果你打得激进，这个数会很低。可以先看 K/D：KD < 1 的时候，存活率低是正常的。

某个指标是「—」

样本不足时不给数（比如某把枪只开了一枪）。这是故意的——宁可空着也不给一个没意义的百分比。

为什么没有暂停 / 投降统计

awpy 3.1.1 拿不到 timeout / pause 事件，也拿不到投降的独立原因字段。只能按回合时长 >115 秒推断「可能有暂停」，无法知道哪队叫的。

投掷者是怎么拿到的

awpy 的 grenades 表里投掷者字段全是空值，所以一开始只能数总数。后来改用 demoparser2 的引爆事件 —— smokegrenade_detonate / flashbang_detonate / hegrenade_detonate / inferno_startburn / decoy_started —— 这些事件自带 user_steamid，能精确到人。

投出数可能小于购买数，这不是 bug。买了道具但死在手里的不会出现在投出统计里，实测全场投出率约 55%。捡起别人的道具再投出去会算进你的投出数，所以它也可能大于购买数。
